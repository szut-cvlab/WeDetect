# WeDetect 项目代码结构解析

> 基于 `README.md` + 实际源码（`wedetect/`、`config/`、`wedetect_ref/`、`wedetect_anything/`）梳理。

## 0. 总体定位

WeDetect 是腾讯微信视觉开源的**开放词汇目标检测**框架，整体建立在 **MMDetection 3.x** 之上（用 `mmdet` 的 `MODELS` 注册器、`train.py/test.py/vis.py` 标准入口、`mmengine` 配置系统）。代码并非从零搭训练框架，而是把 YOLO-World 的 mmyolo 实现改造为「双塔无融合 + 检索式」范式，并外挂两个子项目（Ref / Anything）。

三个模型家族在仓库里的落地方式：

| 家族 | 论文角色 | 代码载体 |
|------|----------|----------|
| WeDetect | 双塔 OVD 检测底座 | `YOLOWorldDetector` + 在线 XLM-R 文本塔 |
| WeDetect-Uni | 冻结底座、只训 objectness prompt | `SimpleYOLOWorldDetector`（`num_prompts` 可学习向量，类合并为 `object`） |
| WeDetect-Ref | Qwen3-VL 当分类器，一次前向并行打分 | 独立子项目 `wedetect_ref/`（LMM，不依赖 mmcv） |

### 常见文本塔的区别：

OVD 常见的三个文本塔——**CLIP text encoder**、**BERT(GDINO/GLIP 用)**、**XLM-RoBERTa(WeDetect 用)**，架构上同属 Transformer encoder(双向自注意力)家族，但预训练目标、分词、输出粒度与用法范式差别很大。

- **CLIP text encoder**（YOLO-World）：从零训的一个 Transformer encoder(12 层、8 头、63M、77 token 上限)。分词用 **BPE**(GPT 系)，预训练目标是**图文对比学习**(~4亿图文对)，句表征靠 **[EOS] (End Of Sequence)向量**，适合"整词↔整图"检索。
- **BERT(GDINO/GLIP 用)**：标准预训练 **bert-base-uncased**（输入上限 **512 token**，含 `[CLS]`/`[SEP]`），分词用 **WordPiece**(~30k)，预训练目标是 **MLM + NSP**（纯语言）。输出是**上下文 token 级**表征——每个词依赖全句上下文。这是融合式短语 grounding 的基础：靠 `tokens_positive` 标出描述某框的 token 区间做对齐，保留句内组合性("红车左侧蓝卡车")，代价是得上融合层 + 标 token 级监督、推理重。
- **XLM-RoBERTa**（WeDetect 实际文本塔）：架构与 BERT **完全相同**(Transformer encoder + MLM)，但**训练多语**(从commoncrawl-一个公开的超大规模网页爬取语料库按 100 种语言过滤出来的 CC100)、词表更大(SentencePiece)。WeDetect 用它替换 CLIP 文本 encoder，原因：CLIP 文本塔太弱(63M、77 token 上限、仅英文)；XLM-R 表征更强 + 多语（微信数千中文类目落地，一套权重中英两用）。**关键用法**：尽管 XLM-R 能出上下文 token，WeDetect 仍把**每个类名独立编码成单个 embedding**(无句子语境)，保持"检索式"范式——分类 = 区域 ⊙ 类名 embedding 点积，而非 GDINO 那样做句内 token 对齐。
  - XLM = "Cross-lingual Language Model"——跨语言版本
  - RoBERTa = "Robustly optimized BERT pretraining Approach"——就是用更好训练配方重训 BERT

| 维度 | CLIP text encoder | BERT(GDINO/GLIP) | XLM-RoBERTa(WeDetect) |
|------|------|------|------|
| 是否 BERT | 否(同族，从零训) | 是(标准预训练) | 是(同架构，多语版) |
| 参数量 | base 63M / large 123M | 110M(bert-base) | base 270M / large 560M |
| 最长 token | 77 | 512 | 512 |
| 预训练 | 图文对比(从零) | MLM + NSP(纯语言) | MLM(多语) |
| 分词 | BPE ~49k | WordPiece ~30k | SentencePiece ~250k |
| 输出 | 句级对齐向量为主 | 上下文 token 级 | 同 BERT，但**逐类名独立编码成单向量** |
| OVD 用法 | 每类名→单 embedding(检索) | 整句 token + `tokens_positive`(融合) | 每类名→单 embedding(检索) |
| 组合性 | 丢失句内组合 | 保留 | 丢失(刻意独立编码) |
| 语言 | 仅英文 | 仅英文 | 多语(中英共用) |

> 注：XLM-R 因为词表较大 250k × 768 ≈ 192M，所以同架构、参数量随词表涨

### 三种分词器对比（BPE / WordPiece / SentencePiece）

三者都是**子词(subword)**分词，核心思想一致：把词拆成高频共现的片段，既控住词表大小又能处理未登录词(OOV)。差别在合并准则与是否依赖空格/语言。

- **BPE(Byte-Pair Encoding)**，CLIP / GPT 系用：
  - 从字符(或字节)起步，迭代合并"出现频率最高"的相邻片段，构建词表。
  - GPT-2 用 **byte-level BPE**(在字节上操作)，任意 Unicode 都不会成 `<unk>`。
  - CLIP 用 BPE，词表 ~49k。
- **WordPiece**，BERT 系用：
  - 与 BPE 同属合并式，但**合并准则不同**——按似然/互信息 `p(ab)/(p(a)p(b))` 选最优切分，而非纯频率。
  - 用 `##` 前缀标记"这是一个词的中间片段"(如 `playing` → `play` + `##ing`)。
  - 依赖**空格预分词**(先按词切开再子词化)，对无空格语言(中文/日文)不友好。bert-base 词表 ~30k。
- **SentencePiece**，XLM-R / T5 / 多语模型用：
  - 一个**框架**，可实现 BPE 也可实现 **Unigram**(XLM-R 用的是 Unigram LM 模型)。
  - **关键差异**：把空格也当普通字符(用 `▁` 表示)，**不依赖空格预分词**——所以天然适配中文、日文等无空格语言，且能跨 100 种语言共用一套词表。
  - XLM-R 用 SentencePiece，词表 ~250k(比前两者大得多，因为要覆盖百种语言)。

| 分词器 | 代表模型 | 合并准则 | 是否依赖空格 | 中文友好 | 词表(参考) |
|--------|----------|----------|--------------|----------|------------|
| BPE | CLIP / GPT-2 | 频率最高相邻对 | 否(byte-level) | 一般 | ~49k |
| WordPiece | BERT | 似然/互信息 | 是(先按词切) | 差 | ~30k |
| SentencePiece(Unigram) | XLM-R / T5 | Unigram 概率 | 否(空格即字符) | 好 | ~250k |

> 这也是 WeDetect 选 XLM-R 的隐性好处之一：SentencePiece 对中文零适配成本，配合"无语言专属 token"，一套权重直接中英两用。

### 现代主流 LLM 的分词器（多语 + 海量数据时代）

结论：**生成式 LLM 几乎清一色用 BPE**（要么裸 byte-level BPE，要么 SentencePiece 的 BPE 模式），**WordPiece 基本只剩 BERT 时代的编码器模型在用**。

| 模型 | 分词器 | 实现 / 词表 | 备注 |
|------|--------|-------------|------|
| GPT-3.5 / 4 | byte-level BPE | `tiktoken` 的 `cl100k_base`(~100k) | 字节级，任意语言不 `<unk>` |
| GPT-4o / o-series | byte-level BPE | `o200k_base`(~200k) | 词表更大、多语更强 |
| Claude | BPE 系(未全公开) | 专有，大词表 | 官方只确认是 BPE 类 |
| Qwen2 / 2.5 / 3 | BPE | HF `tokenizers`，词表 151,936 | 多语，中文友好 |
| Gemini | 专有(类 SentencePiece) | 未公开 | — |

要点：
- **"BPE" 与 "SentencePiece" 界限已模糊**：SentencePiece 只是框架，既能跑 Unigram(XLM-R)也能跑 BPE
- **WordPiece 出局**：依赖空格预分词、对中文不友好、词表偏小，只留存在 BERT/DistilBERT 等**编码器**模型；所有**生成式** LLM 都不用了。
- **词表随数据膨胀**：CLIP 时代 49k、BERT 30k → 现在 Qwen 152k、GPT-4o 200k、LLaMA3 128k，词表大小与"多语 + 海量数据"正相关。

## 2. 检测核心包 `wedetect/models/`

### 2.1 双塔主干 `backbones/mm_backbone.py`

- **`ConvNextVisionBackbone`**（line 260）：ConvNeXt，非 torchvision 版。四个尺寸：
  - `tiny`：`dims=[96,192,384,768]`，`depths=[3,3,9,3]` —— **✓ 实际训练**(对应 `wedetect_tiny.py`)
  - `base`：`dims=[128,256,512,1024]` —— **✓ 主力尺寸**(对应 `wedetect_base.py`；Uni / 各类微调配置也基于 base)
  - `large`：`dims=[192,384,768,1536]` —— **✓ 实际训练**(对应 `wedetect_large.py`)
  - `xlarge`：`dims=[256,512,1024,2048]`（额外 `down_mlp` 把 2048 降到 1024）—— **✗ 实际未训练**
  - `forward` 返回 **4 张层级特征图**（[0,1,2,3] 四级），天然多尺度，正好喂 neck。这是选 ConvNeXt 而非 ViT 的根本原因。
  - **下游 neck / head 定义**：
    - **Neck**：`CSPRepBiFPANNeck`（`necks/yolo_world_pafpn.py:988`，继承 `BaseYOLONeck`@`base_yolo_neck.py:15`）——FPN+PAFPN 双向融合，输出 N 张多尺度金字塔特征图（分辨率不变，保留多尺度）。
    - **Head**：`YOLOWorldHead`（`dense_heads/yolo_world_head.py:357`，模块 `YOLOWorldHeadModule`@:138）+ 对比头 `BNContrastiveHead`（@:69）——逐金字塔层级对图像网格特征与文本塔 embedding 做 `einsum('bchw,bkc->bkhw')` 密集对比，得到逐位置逐类的检测分数。
- **`XLMRobertaLanguageBackbone`**（line 342）：文本塔，初始化自 XLM-RoBERTa（base 270M / large 560M）。末尾挂一个线性投影 head（base/tiny 768→768，large 1024→768，xlarge 1024→1024）。**每个类名独立编码成单个 embedding**（见 `forward`：把 `[["行人"],["人"],...]` 展平后 tokenize，逐类出向量）。
- **`MultiModalYOLOBackbone`**（line 598）：把 image_model + text_model 包在一起，提供 `forward / forward_image / forward_text`。关键开关 `with_text_model`：闭集微调时置 False，**删除文本塔**，分类头锁死在预编码 npy 词表。
- `HuggingCLIPVisionBackbone` / `HuggingCLIPLanguageBackbone`：HF 的 ViT-CLIP 视觉塔 + CLIP 文本塔。**都是死代码**——只在 `wedetect/models/backbones/__init__.py` 注册，无任何 config 实例化。发布代码里视觉塔用 `ConvNextVisionBackbone`、文本塔用 `XLMRobertaLanguageBackbone`。
- **阶段 1 预训练代码未发布**

### 2.2 检测器 `detectors/`

两个检测器类，是理解「OVD 检测」与「Uni/闭集」差异的核心：

- **`YOLOWorldDetector`**（`yolo_world.py`）：**双塔完整版**。
  - `reparameterize(texts)`：把 `--text` 的中文类名交给 `backbone.forward_text` 编码成 `text_feats` 并缓存（在线文本塔）。
  - `predict`：`img_feats = backbone.forward_image`，**`bbox_head.num_classes = txt_feats[0].shape[0]`**——测试类数由传入文本数动态决定，即「检索式 OVD，词表不写死在权重里」。
  - `extract_feat` 里 `mm_neck=False` 时 neck 只吃 `img_feats`（**无融合**，文本不参与 neck）。
- **`SimpleYOLOWorldDetector`**（line 119）：**Uni / 闭集版**。
  - 不在线编码文本，改为学一组 **`num_prompts` 个可学习 embedding**（`prompt_dim` 维，随机初始化或读 npy）。
  - 推理时 `txt_feats = self.embeddings`，head 直接拿它当分类权重。
  - Uni 配置里 `num_prompts=256`、类合并为 `object`：256 路中只有第 0 路受监督，其余是死权重（详见论文笔记 Q2/Q4）。`reparameterized=True` 时连 embedding 都不要（闭集，分类头锁死 npy）。

### 2.3 neck `necks/`

- **`CSPRepBiFPANNeck`**（`yolo_world_pafpn.py:988`）：自研 neck，**不含任何图文融合层**（替换 YOLO-World 的 RepVL-PAN），是「坚守无融合检索范式」的组件级体现。把 backbone 的 4 级特征（stride 4/8/16/32）压成 **3 个输出层级（stride 8/16/32）**，stride-4 那级只参与 top-down 融合不单独输出；通道 base=[128,256,512]（`scale_factor=1.0`）、large=[192,384,768]（1.5），见 `eval_recall.py:1249-1256`。注意 `wedetect_base.py:76` head 写的 `in_channels=[256,512,1024]` 与 neck 实际输出对不上（疑似 YOLO-World 抄来的陈旧值），以推理脚本为准。

### 2.4 检测头 `dense_heads/yolo_world_head.py`

- **`YOLOWorldHead`** + **`BNContrastiveHead`**（line 69）：分类 = **检索**。
  - `forward(x, w)`：`x`（图像网格特征）和 `w`（类名 embedding）都 L2 归一化，做 `einsum('bchw,bkc->bkhw')` 得到每类响应图，再 `× logit_scale.exp() + bias`。即「网格特征 ⊙ 全部类 embedding 一步出所有类响应」，对应论文「一次图像前向 + 一次批点积」。
  - 回归沿用 YOLO-World 血缘：`WeDetectDistancePointBBoxCoder`（anchor-free 点回归）、`DistributionFocalLoss`（DFL）、`BatchTaskAlignedAssigner`（TAL，task_modules/assigner）。
  - 损失：`CrossEntropyLoss(sigmoid)` + `mmyoloIoULoss(ciou)` + `DistributionFocalLoss`，权重 `0.5 / 7.5 / 1.5/4`（config 默认值）。

### 2.5 数据预处理与数据集 `datasets/`

- `models/data_preprocessors/data_preprocessor.py` → **`YOLOWDetDataPreprocessor`**：`mean=0, std=255, bgr_to_rgb=True`（像素归一化到 [0,1] 并转 RGB）。
- `mm_dataset.py` → **`MultiModalDataset`**：包一层基础 dataset + `class_text_path`（中文类名 json）；评测时按该 json 决定测试词表。
- 专用 resize：`WeDetectKeepRatioResize` + `WeDetectLetterResize`（保持比例 + letterbox，pad=114），tiny/base是(640, 640) large是(1280, 1280)。
- `transformers/mm_transforms.py` → **`LoadText`**：把 `class_text_path` 的中文名载入 sample 的 `texts` 字段。
- 基础 dataset：`WeCocoDataset`、`YOLOv5LVISV1Dataset`（LVIS 走 YOLOv5 风格 loader）、`WeConcatDataset` 等。

## 3. 配置体系 `config/`

- **`wedetect_tiny/base/large.py`(检测底座)**：`YOLOWorldDetector` + `MultiModalYOLOBackbone`(ConvNext+XLM-R) + `CSPRepBiFPANNeck`。
  - `num_training_classes=80` = 训练词表大小（本配置 COCO 80 类）。**换数据集训练就改这里**：它进 head 作为训练时 `self.num_classes`，loss 里 reshape 分类预测要求它 = 每图 prompt 数 K=`txt_feats[0].shape[0]`，所以必须和训练集词表大小一致。
  - `RandomLoadText.max_num_samples=80`(`mm_transforms.py:16-17`)是**每图采样上限**，决定 K 的上界(图上正类 + 随机负类)。`num_training_classes` 与 `max_num_samples` 是两个独立旋钮、恰好都=80（因发布的 COCO 训练配方词表即 80 类）。
  - head 是动态对比头(推理 `num_classes=txt_feats` 长度)，推理可零样本跑任意词表(LVIS-1203、自定义 `--text`)。注意：**发布的 checkpoint 是论文 20M 图/330M 框数据训的**（多粒度层级标签+公开集类名，见论文笔记 §3.2/3.3），"80 类"只是**用本仓库 config 微调 COCO** 时的监督词表，不是原训练词表；评测 config 喂中文类名只是 prompt 选择（论文笔记 Q4）。
- **`wedetect_uni_base_finetune.py`(Uni)**：`SimpleYOLOWorldDetector`，类合并 `object`，`num_prompts=256`；默认只训 prompt，解冻 head/neck 会致 embedding 漂移。
- **`wedetect_base_coco_full_tuning_8xbs4_2e-5.py`(OV 微调)**：文本塔保留且 `lr_mult=0.01` 更新，可换任意 `--text`。
- **`wedetect_base_coco_vision_encoder_8xbs4_2e-5.py`(闭集微调)**：`with_text_model=False` 删除文本塔，分类锁死 npy。
- **带 `_mask_refine.py`(掩码精框)**：仅训练集有实例掩码时有用(`mask2bbox` 反算紧框)。

> 注意：`config` 里 **评测用的是中文类名文件**（如 `lvis_v1_zh_class_texts.json`），即榜单数字是中文 prompt 跑出来的。

## 4. 推理 / 训练脚本（根目录）

- **`infer_wedetect.py`**：`init_detector` → 解析 `--text`（中文、英文逗号分隔，末尾补 `[[' ']]` 当背景）→ `model.reparameterize(texts)` → 逐图 `model.test_step` → 可视化（PIL + `simsun.ttc` 中文字体）。
- **`generate_proposal.py`**：加载 Uni checkpoint，输出全图候选框（`--score_thre` 过滤）。是 Ref 的前置步骤。
- **`generate_class_embedding.py`**：闭集微调前把固定中文类名离线编码成 npy，供 `with_text_model=False` 配置初始化分类头。
- **`infer_wedetect_ref.py`**：加载 Ref + Uni 两个 checkpoint，对 Uni 的候选列表用 Qwen3-VL 一次前向并行打分，挑出满足 query 的框（单 query）。
- 训练：`dist_train.sh config/xxx.py N`（N 卡）。

## 5. 扩展子项目

### 5.1 `wedetect_ref/`（WeDetect-Ref，LMM 物体分类器）

独立子项目，不依赖 mmcv，基于 Qwen3-VL（2B/4B）。它不回归新框，而是把主检测器（Uni/WeDetect）的候选框变成 `<object>` token，连同图像和文本一起喂给 LLM 做区域判断。两个模型文件共用同一套"候选框→多尺度 RoIAlign 拼接→线性投影压成单 `<object>` token→拼进 LLM"的管线，区别只在输出头：`qwen3vl_referring.py` 是判别式，在物体 token 的 hidden 上加 `out_proj` 二分类头（sigmoid focal + 软 IoU 标签）；`qwen3vl_grounding.py` 是生成式，走 `lm_head` + 语言模型 loss，不对框打分（框标签分支是 `pass` 占位）。`vision_process.py` 负责视觉预处理。

**训练**共三个 stage。
- Stage 1 用 `sft.py` + `qwen3vl_grounding.py`（生成式），从 Qwen3-VL-2B-Instruct 起，数据 `pretrain_data_685k.json`，同时冻结视觉塔和 LLM，只训练新加的 RoIAlign/`⟨object⟩` 投影器（`lm_head` 保持可训），lr=1e-3，把候选框编码成 LLM 能吃的 `<object>` token。
- Stage 2 仍用 `sft.py` + `qwen3vl_grounding.py`，从 stage1 起，数据 `stage2_data_1685k_filtered.json`，只冻视觉塔、放开 LLM，训练 LLM 和投影器，lr=1e-5，做区域感知 SFT，通过监督微调让 LLM 真正理解并围绕 <object> 区域来生成/回答。。
- Stage 3 切到 `sft_referring.py` + `qwen3vl_referring.py`（判别式），从 stage2 起，数据 `stage3_data_3110k_repeat_humanref_neg5.json` 配 `proposals_allv6.json` 候选框，只冻视觉塔，训练 LLM 和 `out_proj`，lr=1e-5：每个候选框的 `<object>` token 经 `out_proj` 出一个标量，标签取与 gt 的 IoU（`IoU>0.5` 取 IoU 值、否则 0），用 sigmoid focal 训练。
- HF 只有 refcoco 评测标注+proposals；训练 JSON 无官方下载,需按 wedetect_ref/README.md 的格式从上游数据集自建。

**推理**走 `eval_grounding/eval.py`，加载的是 Stage 3 的 referring 模型。对每张图取候选框，逐框 RoIAlign→`⟨object⟩` token，和查询文本一起过 LLM，`out_proj` 给每个候选框打分并 sigmoid，按分数取 top-K（`--num_select`）作为结果——本质是候选框重排/选择，不回归新框。局限是单次前向只支持一个 query，多类检测要逐 query 推理再合并。

### 5.2 `wedetect_anything/`（论文未涵盖，2026-06 放出）
- 免 prompt 万物检测：候选阶段纯视觉（Uni 的 256 可学习 prompt），导出 ONNX 只吃一张图；把 embedding 与**预编码的数千中文类目词表**（`prompt_free.npy`，XLM-R 768 维 L2 归一化）做点积 + sigmoid + argmax 出类别——文本塔从「在线编码」换成「离线词表查表」。
- `infer_anything.py` / `models.py` / `export_onnx.py` / `wedetect_unified_app.py`（Gradio demo）。

### 5.3 评测 / 部署
- `eval_recall/`：Uni 提议召回（AR@100/@300，纯几何 IoU，不涉及分类）——REC 天花板。

## 6. 一次检测推理的数据流（retrieval OVD）

```
--text "行人,人,..."  ──► reparameterize
                            │  XLMRobertaLanguageBackbone.forward_text
                            ▼
                        text_feats  [K, 768]  (K=类名数，缓存)
image ──► ConvNextVisionBackbone.forward_image ──► 4 级特征图 (stride 4/8/16/32)
                            │
                            ▼
                    CSPRepBiFPANNeck (无融合) ──► 3 级特征 (stride 8/16/32)
                            │
                            ▼
            YOLOWorldHead: BNContrastiveHead(归一化网格特征 ⊙ text_feats)
                            │   ×logit_scale + bias ──► 每类响应图
                            ▼
             anchor-free 回归(DFL) + TAL 分配 + NMS ──► 检测结果
```
要点：**图像只前向一次，文本只编码一次（可缓存）**，分类是矩阵点积一步出全部类。
