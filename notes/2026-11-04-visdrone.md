# VisDrone 零样本摸底（WeDetect）

目的：公开权重、不微调，判断崩在哪一层——分类（图文对齐）/ 定位（Uni 候选）/ 分辨率（输入太小）。结论汇总在本文件末节。

已就绪：`data/VisDrone/{images,labels}/{train,val,test}` 已是 YOLO 格式（6471/548/1610）；权重有 base / tiny / base_uni / Ref-2B。

输入尺寸：test-dev GT 短边中位 17px，letterbox 到 640 后 **52% 的框 <8px（不足一个 P3 grid cell）**，1280 降到 24%。所以 640 与 1280 各跑一遍。

## 口径

- 主集 test-dev（1610）
- prompt 表顺序 = YOLO 类号 0–9（类名列在 `build_coco.py`），同一套类名换英文再跑一遍。
- 按目标大小分四档（<16 / 16–32 / 32–64 / >64 像素）分别算 AP/AR，看崩在哪一档。
- AP 双口径：maxDets=100（与公开榜可比）+ maxDets=500 的 IoU0.5 P/R/F1（每图 GT 均值 46.6，最大 461）。

## 步骤

1. **数据整形**（已做）`eval_visdrone/build_coco.py` → 一份 `data/VisDrone/annotations/visdrone_testdev_coco.json`（1610 图 / 75,102 框，categories 10）+ 2 张 prompt 表（zh10 主跑 / en10 对照）。metainfo 类名由 config `from eval_visdrone.build_coco import CATS`，与 json 同源。
2. **config**：`config/wedetect_{base,tiny}_visdrone.py`，只写差异叶子，类名 import 自 build_coco

## 坑

- `MultiModalDataset` 的类数 assert 上游注释掉了（`mm_dataset.py:36`），脚本自己加。
- mmdet 按 `metainfo['classes']` 的**名字**反查 category_id（`coco.py:70`），默认是 COCO 80 个英文名；非 COCO 数据集必须显式传 `metainfo`（config 里 `metainfo=dict(classes=CATS)`，CATS 从 build_coco import），否则 GT 被静默丢光。
- 在线 CocoMetric 用 `self.cat_ids[label]` 映射（`coco_metric.py:243`），prompt 条数超过 json categories 数会 IndexError —— json 固定 10 类。
- WeDetect 自标 15M 图源未开源，无法排除 VisDrone 帧已被爬入。

**结论**：WeDetect 在 VisDrone 上零样本基本不可用（AP 9.6，COCO 上是 44.9），问题出在底座，两层都崩：

1. **候选层**：Uni 对小目标开不出框——<16² 的目标召回 640 输入只有 3.9%（大目标 75.4%）。不是候选数不够：每图打满 500 个候选，往上加也只涨 1 个点。
2. **对齐层**：就算框对了，打分也把大半丢掉——候选能盖住 30.6% 的 GT，最终检测 AP 只有 9.6%。

已排除：模型太小（tiny 只差 2.5 点）、词表大小（24 词表不掉分）、prompt 语言（英文略降）、prompt 翻译（"人群"改"人"0.1→0.7）。**分辨率是唯一确认的正向因素**：检测 AP 1280 涨 5 点；Uni 候选 <16² 召回 3.9→15.0（4 倍）、16–32² 31→47，说明小目标候选崩一大半是输入分辨率造成的。

**下一步**：
- 不做 VisDrone 10 类闭集微调——zero-shot 模型微调成闭集检测器等于自废卖点。
- **低空域 OVD 数据集**：低空无人机视角、类别开放（远不止 10 类）、混入预训练分布做域适配训练，留出类目验证开放词表没丢；VisDrone/UAVDT 作评测基准。计划见 `notes/2026-11-04-uav-ovd-plan.md`。
